# 橙子项目管理平台统一 UI 改造实施计划

> 目标：在不改变业务接口、路由和状态管理的前提下，将整个 Vue 前端统一为深海军蓝 + 薄荷绿的简约科技风格。

## 文件范围

- `frontend/src/styles/index.css`：统一设计令牌和 Element Plus 覆盖。
- `frontend/src/layout/index.vue`：重做侧边栏、顶栏、用户区和窄屏布局。
- `frontend/src/views/login/index.vue`：迁移登录页面视觉。
- `frontend/src/views/dashboard/index.vue`：迁移工作台视觉。
- `frontend/src/views/product/`：统一产品、需求、发布页面。
- `frontend/src/views/project/`：统一项目、详情、看板页面。
- `frontend/src/views/qa/`：统一 Bug、用例、测试单页面。
- `frontend/src/views/stats/index.vue`：统一统计页面。
- `frontend/src/views/system/`：统一系统管理页面。
- `frontend/src/components/`：统一状态、优先级、附件、动态组件。

## 任务一：建立全局设计令牌

1. 读取 `frontend/src/styles/index.css` 的现有变量和 Element Plus 覆盖，保留语义变量名称，避免页面模板失效。
2. 将背景、主色和布局变量改为：页面背景 `#F4F7FB`，导航 `#10243F`，强调色 `#8DF0C5`，正文 `#172033`，次级文字 `#738198`。
3. 增加 `--nav-*`、`--surface-*`、`--focus-ring` 和统一间距变量，确保局部页面可直接复用。
4. 将主按钮、菜单激活项、分页、标签、输入框、表格、弹窗、下拉菜单的 Element Plus 覆盖统一到新令牌。
5. 保留成功、警告、危险颜色，确保状态标签仍表达业务语义。
6. 增加 `.app-shell`、`.page-container`、`.page-card`、`.filter-bar`、`.table-toolbar`、`.empty-state` 的统一间距与响应式规则。
7. 运行 `frontend` 的 `npm run build`，确认全局变量变更没有造成语法或编译错误。

## 任务二：改造主布局

1. 读取 `frontend/src/layout/index.vue` 的模板、脚本和样式，保持菜单数据、通知、个人中心、帮助文档和退出登录逻辑不变。
2. 将侧边栏背景改为深海军蓝，品牌区使用字母标识或简洁图形，不再依赖 emoji 作为主要品牌元素。
3. 为菜单项增加统一的图标尺寸、激活指示线、悬停态和子菜单缩进。
4. 将用户卡片改为深色导航底部的轻量信息块，保持头像、姓名、角色和点击行为。
5. 将顶栏改为白色半透明表面，保留页面标题、搜索框、通知、帮助和用户下拉菜单。
6. 增加窄屏规则：内容区保持可滚动，搜索框缩短，用户姓名可隐藏，侧栏宽度不挤压主内容。
7. 启动前端开发服务，验证菜单跳转、搜索回车、通知弹窗、帮助弹窗、个人中心和退出登录入口。

## 任务三：迁移登录与工作台

1. 读取 `frontend/src/views/login/index.vue` 和 `frontend/src/views/dashboard/index.vue`，只调整模板中的视觉类名和局部样式，不修改登录请求、统计请求和图表数据逻辑。
2. 登录页采用左右分栏：深色品牌面板 + 白色登录表单；窄屏时隐藏或折叠品牌面板，确保表单可用。
3. 工作台采用页面标题区、指标卡、燃尽图、Bug 分布、待办和动态卡片的统一卡片容器。
4. 统一数字、标题、辅助说明和状态趋势的字体层级，避免使用与新设计冲突的橙色大面积背景。
5. 为图表容器增加最小高度和窄屏适配，防止 ECharts 初始化时容器高度为 0。
6. 验证登录成功、登录失败提示、工作台数据加载、图表渲染和空数据状态。

## 任务四：迁移产品与项目页面

1. 读取 `frontend/src/views/product/` 和 `frontend/src/views/project/` 页面，识别局部硬编码颜色、背景、边框和按钮样式。
2. 将产品列表、需求列表、发布列表统一为标题区 + 筛选卡 + 表格卡 + 分页结构。
3. 将需求和发布状态、优先级迁移到统一标签语义，不改变现有状态文本和操作。
4. 将项目列表、项目详情统一为项目摘要卡、信息分区和关联数据卡。
5. 将迭代看板改为低对比状态列 + 白色任务卡，保留拖拽和状态变更逻辑。
6. 为表格和看板增加横向滚动保护，窄屏下不裁剪关键操作。
7. 验证产品、需求、发布、项目、项目详情和看板的新增、编辑、删除、筛选、分页及跳转操作。

## 任务五：迁移质量与统计页面

1. 读取 `frontend/src/views/qa/` 和 `frontend/src/views/stats/index.vue`，保留 API 请求、表单校验和图表配置。
2. 将 Bug 页面统一为筛选工具栏、表格、优先级/严重程度标签和分页布局。
3. 将测试用例、测试单页面的空状态、工具栏和表格统一到公共卡片样式。
4. 将统计页面的指标、燃尽图、任务分布和 Bug 分布分成独立内容卡，保证图表图例和筛选控件可读。
5. 验证 Bug 新增、编辑、状态流转、用例新增、测试单操作和统计筛选。

## 任务六：迁移系统管理页面与共享组件

1. 读取 `frontend/src/views/system/` 和 `frontend/src/components/`，只修改展示层类名和局部样式。
2. 统一用户、角色、权限、部门、日志、配置页面的表格、树、表单、弹窗和分页样式。
3. 将 `StatusTag.vue`、`PriorityTag.vue` 的颜色映射集中到语义色变量，确保产品、任务、Bug 共用一致表现。
4. 调整 `AttachmentList.vue` 和 `ActivityPanel.vue` 的边框、间距、空状态和交互反馈。
5. 验证用户、角色、权限、部门、日志和系统配置页面的查询、保存、删除、树操作和弹窗交互。

## 任务七：构建与页面巡检

1. 在 `frontend` 目录运行 `npm run build`，确认构建成功。
2. 启动 `npm run dev`，检查登录、工作台、产品列表、需求、项目详情、看板、Bug、统计、用户管理和系统配置页面。
3. 调整桌面宽度和窄窗口宽度，重点检查侧栏、表格、看板、筛选栏、弹窗和图表是否溢出。
4. 使用浏览器控制台检查运行时错误、未捕获 Promise 和图表初始化错误。
5. 对发现的问题按“布局结构、颜色层级、交互反馈、响应式”顺序逐项修复，每次修复后重新构建。
6. 最终记录已验证页面和仍需后续优化的非阻塞问题。

## 验收标准

- `npm run build` 成功。
- 现有路由、API、权限指令和业务操作不被改变。
- 全部页面统一使用深海军蓝导航、薄荷绿强调色、浅灰蓝背景和白色卡片。
- 主要页面在桌面和窄窗口下可用，无明显横向溢出。
- 登录、导航、搜索、通知、个人中心、表格、表单、分页、看板和图表功能完成回归检查。
