# 橙子项目管理平台统一 UI 改造设计

## 目标

在不改变现有业务接口、路由和核心交互逻辑的前提下，将 Vue 3 + Element Plus 前端统一改造成简约科技风格。视觉基准来自已确认的 HTML 原型：深海军蓝导航、薄荷绿强调色、浅灰蓝背景、白色内容卡片和克制的阴影。

## 项目上下文

前端位于 `frontend/`，使用 Vue 3、Vite、Element Plus、Pinia、Axios 和 ECharts。页面范围包括登录、工作台、产品管理、项目管理、质量中心、统计报表和系统管理；现有全局样式与主布局已经集中在 `frontend/src/styles/index.css` 和 `frontend/src/layout/index.vue`，适合先建立统一设计系统，再通过共享规则覆盖业务页面。

## 视觉方向

- 页面背景使用 `#F4F7FB`，避免大面积渐变造成视觉噪音。
- 侧边栏使用 `#10243F`，导航文字使用低饱和蓝灰色，激活项使用较亮的深蓝背景并配薄荷绿强调。
- 主操作色使用 `#8DF0C5`，深色文字保证按钮和关键状态的可读性。
- 内容卡片使用白色、1px 浅边框和轻阴影；圆角控制在 10 至 16px。
- 状态色继续区分成功、警告、危险，不用主色替代语义色。
- 优先使用系统中文字体，避免运行时依赖外部字体服务。
- 动效仅用于导航切换、悬停、弹窗和加载反馈，并支持减少动态效果的系统偏好。

## 信息架构

保留现有路由和权限菜单，统一呈现为：

- 工作台
- 产品管理
- 项目管理
- 质量中心
- 统计报表
- 系统管理

主布局保留侧边栏、顶栏和内容区三段式结构。侧边栏负责模块导航和当前用户信息；顶栏负责当前页面标题、全局搜索、通知、帮助和个人菜单；内容区负责页面业务内容和滚动。

## 页面规范

### 列表页

页面顶部使用标题与主操作，筛选区单独作为浅边框卡片，表格、分页和空状态遵循统一间距。筛选项在窄窗口自动换行，表格允许横向滚动而不挤压关键列。

### 详情页

顶部展示对象名称、状态和关键元信息；主体按信息卡、关联记录和操作区组织。保留现有详情数据与操作，只调整容器、间距和状态展示。

### 看板页

顶部保留项目、迭代上下文；状态列使用低对比背景，任务卡片使用白色和轻边框；拖拽状态、悬停和空列状态要有明确反馈。

### 统计页

指标卡统一为短标题、大数字和辅助趋势信息；图表放入白色内容卡片，筛选条件与图例清晰分层。

### 系统页

用户、角色、权限、部门、日志和配置页面共享表格、树、表单、弹窗和分页样式，不改变权限指令和接口调用。

### 登录页

保留登录能力和演示账号提示，使用深海军蓝品牌面板与薄荷绿操作色，简化装饰背景，确保窄屏下表单优先可见。

## 文件边界

- `frontend/src/styles/index.css`：颜色、间距、圆角、阴影、Element Plus 覆盖和公共工具类。
- `frontend/src/layout/index.vue`：导航、顶栏、用户区、全局搜索、通知和响应式布局。
- `frontend/src/components/`：状态标签、优先级标签、附件和动态面板的统一视觉。
- `frontend/src/views/login/index.vue`：登录页视觉迁移。
- `frontend/src/views/dashboard/index.vue`：工作台视觉迁移。
- `frontend/src/views/product/`：产品、需求、发布页面的布局和组件样式。
- `frontend/src/views/project/`：项目列表、项目详情和迭代看板的布局和组件样式。
- `frontend/src/views/qa/`：Bug、测试用例和测试单页面的布局和组件样式。
- `frontend/src/views/stats/index.vue`：统计报表页面视觉迁移。
- `frontend/src/views/system/`：系统管理页面视觉迁移。

不修改 `frontend/src/api/`、`frontend/src/store/`、后端接口和数据库结构，除非验证发现页面样式改造暴露出已有的非 UI 阻塞错误。

## 验证标准

- `npm run build` 成功完成且无编译错误。
- 登录、导航、全局搜索、通知、个人菜单等既有交互不回归。
- 所有主要页面在桌面宽度下无明显溢出；窄窗口下导航、表格和表单可用。
- 所有页面使用同一套背景、卡片、按钮、输入框、表格、标签、弹窗和分页视觉。
- 焦点状态清晰，文字与背景有足够对比度，动画不会阻塞业务操作。
- 视觉检查覆盖工作台、产品列表、需求、项目详情、看板、Bug、统计、用户管理和系统配置页面。

## 风险与取舍

由于当前工作区存在既有未提交修改，本次改造只触碰前端 UI 相关文件，不重置或覆盖其他修改。现有部分页面可能包含局部样式和历史视觉规则，优先通过全局设计系统统一，再对明显冲突的局部样式做最小调整，避免大规模重写业务模板。
